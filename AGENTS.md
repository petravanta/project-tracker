# Notes for coding agents

Follow the shared standards in https://github.com/petravanta/general/blob/main/STANDARDS.md (hub link, theme switch, shared look, user data). Take patterns from there, not from the other apps. This file only adds what's specific to Project Tracker.

- The app is `index.html` with no build step. Serve the folder (`python3 -m http.server`) to run it.
- There is no built-in knowledge, so there is no `data/` folder. If the app ever ships project templates, they go in `data/` as the standards describe.
- The document (`projectTracker.data` in `localStorage`) follows the standards' *User data* shape: `projects` and `tasks` records with `id` and `u`, `settings` (zoom, critical path) with `updatedAt`, and `deleted`. Every task names its `project`. Which project is open is kept per device under `projectTracker.current`, outside the document.
- A task is `{ name, start, duration, progress, deps: [{ id, lag }], color, notes, order, parent, group, collapsed }`. `start` is the earliest start the person set, not where the task ends up; `duration` 0 makes it a milestone; `progress` is 0 to 100, and 100 means done; each dep is a finish-to-start link to a task it waits for, with `lag` days after it. `parent` is the id of the group it sits in (null at the top level). A record with `group: true` is a group: it has no dates, duration, progress or deps of its own, `collapsed` says whether it is folded (kept in the document, so it syncs), and deleting it moves its items up to its own parent. `treeOf(tasks)` builds the tree once per render: `kids` by parent, `all` in display order, `rows` (what's visible, skipping folded groups), `depth` and `leaves` (everything that isn't a group). `upgrade()` fixes parents that are missing, in another project or would make a loop.
- `schedule(project, tasks)` is the only place that decides dates. It schedules leaves, then rolls each group up from its leaves (`es`/`ef` spanning them, `progress` weighted by duration, `es: null` when empty), and returns `{ S, end, C, T }` where `T` is the tree. Per task, `S` has `es` and `ef` as day numbers (days since 1970-01-01, see `dn()` / `ds()`), where `ef` is the day after the last day, so a milestone has `ef === es`; `driver`, the task that pushed it latest; and `slack` and `critical` from a backward pass. With a project's `workdays` on, durations and lags count weekdays only, through `calendar()`; new projects have it off (every day counts), since the app is used for recovery plans as well as work. Never use `new Date(string)` on a stored date.
- Row order is each task's `order`, which only has to be right among siblings. `placeTask(id, parent, index)` is the one place that changes `order` or `parent`; `moveTask(id, dir)` (up/down among siblings) and `nestTask(id, dir)` (into the group above / out of its group) are built on it, and the row grips (`dropRow()`), their arrow keys, the editors' Move up/down and *In group* picker all go through them.
- Links can't form a loop: the editor hides tasks that already wait for this one (`waitsFor()`), and `canLink()` guards drag linking. Groups never have deps and can't be linked; a link to or from a task inside a folded group is drawn on the group's row. `schedule()` also skips a loop if one ever arrives in an import.
- Zoom is `settings.zoom`: one of `ZOOM` (pixels per day for day, week, month, quarter and year) or `fit`, which works out pixels per day from the chart's width. The header and weekend shading follow `scaleFor(ppd)`, not the setting, so Fit gets the header that suits its scale. Changing zoom keeps the day in the middle of the view (`zoomAnchor`).
- The Gantt chart is an SVG drawn by `renderGantt()` with colors from CSS tokens (`--c-<color>` for task colors, the same set as Photo Timeline), so it follows the theme without redrawing. The `#chart` scroll box is kept between redraws so pointer capture survives a drag that redraws on every move.
- Google Drive sync (`driveSync()`) follows Nutrition Helper's: one `Project Tracker data.json` found by name, merged with `mergeDocs()`, written a few seconds after each save, and the short-lived token kept under `projectTracker.driveTok`.
